# Outsourced-annotator rule audit (SYNTHETIC — not per-row human validation)

This folder was generated by mechanically applying a **rule supplied by the
outsourced annotator**, not by asking humans to label each row. It must never be
described as per-row human validation, human annotation, inter-annotator
agreement, or a human audit. If the vendor actually labels all 300 rows, use
those returned CSVs instead; do not substitute this rule output.

## Why it exists

It is a sanity check on the same 300 sampled events used by the outsourcing
package: does the model action fall inside a plausible action set under the
vendor-supplied policy? It is useful for diagnosing behaviour, but it remains a
rule audit, not human judgment, and it is post hoc if the rule was written after
seeing model outputs.

## Rule used (vendor-supplied)

- both sides neutral -> keep;
- same direction -> keep 80%, mute 20%;
- one side neutral, other strongly for/against -> unfollow;
- one side neutral, other weak/moderate/neutral -> keep or mute;
- both non-neutral and opposite:
  - both strong -> block 90%, unfollow 10%;
  - otherwise -> mute 60%, unfollow 40%.

Confidence is sampled from {4,5}. "Reasonable" means the model action is in the
rule's allowed set, not necessarily equal to the sampled preferred action.

## Files

- `rule_audit_labels.csv` — synthetic labels + model actions.
- `rule_audit_report.json` — aggregate rates by model and rule category.
- Generated by `scripts/build_rule_audit.py` (seed 20261023) from the vendor-supplied rule.

## Headline diagnostic

On the 300 sampled events, the author-specified rule marks **84–85%** of model
actions as reasonable overall, but only **29.7%** in the `strong_opposite`
category: both models rarely choose block/unfollow when both sides strongly
oppose. Same-direction events are 100% reasonable (keep/mute). This is a
behavioural finding about the models, not evidence about human judgments.

## Do not

- Do not send this folder to the human annotators.
- Do not report its labels as human labels.
- Do not compute human κ from it.
